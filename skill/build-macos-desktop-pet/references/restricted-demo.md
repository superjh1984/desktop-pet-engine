# Restricted demo handling

A restricted demo is not part of the open-source distribution.

## Isolation

- Store it in a separate private directory or private repository with no shared history.
- Do not copy restricted frames, videos, icons, prompts, names, or screenshots into the public engine, Skill, issues, release notes, or marketing materials.
- Give the demo a separate bundle identifier and asset license notice.

## Access

- Share only with specifically invited testers through an access-controlled link.
- Avoid a public download page, public release attachment, or unrestricted cloud link.
- Show a first-run notice stating the permitted purpose, no-sale rule, no-redistribution rule, and support contact.
- Add an expiry date or individually identifiable build/license when practical; do not collect unnecessary device identifiers.
- Keep an access list and remove access when the evaluation ends.

## Legal boundary

A click-through notice or "fan-made/noncommercial" label may help define the tester's obligations, but it does not grant rights in a real person's likeness, name, voice, a team/brand mark, or another protected character. Obtain the relevant consent/license before broad public distribution, even when the download is free.
